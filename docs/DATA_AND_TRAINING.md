# 数据与训练规范

## 必须提供的内容

1. 类别列表：动作 id、中文名称、可观察定义、正确/错误/中性属性、易混淆反例。
2. 固定机位的真实录像：不同人员、服装、光照、速度、工具位置；至少包含正常、错误和不操作。
3. 每个片段的起止时间、标签、group_id。一个片段只有一个主要动作；复杂长录像应切片。
4. 人工确认的训练/验证/测试标签。遮挡、动作混杂、无法判定的片段不要硬标为正确。
5. SOP：哪些步骤、允许顺序、最低时间；如果画面无法观察某条要求，不能用模型声称已验证。

建议先每类采集 50–100 条独立片段作为试验起点，不是保证准确率的最低样本量；重点补充误判反例。至少三个独立人员/分组才能形成三个划分。多段相邻切片不等于多次独立操作。

## JSONL 清单

每行一个 JSON：

```json
{"video":"/data/clips/001.mp4","label":"operate","group_id":"operator01","reviewed":true,"synthetic":false,"source_video":"/data/raw/session01.mp4","start":12.0,"end":15.0}
```

video 可以是绝对路径，或相对 JSONL 文件的路径。reviewed 必须为 JSON 布尔值 true。synthetic 仅用于代码验证，不是正式数据。source_video/start/end 用于检测原录像的重叠片段泄漏。

group_id 由人工定义，建议整个人员使用一个ID；录制场次与人员都需追溯。相同人员和背景同时出现在训练与测试时，结果不能说明能识别新人员。

## 标注与大模型协作

大模型的 proposed_label 不等于训练 label，必须在标注界面确认。对于未知/错误候选，应人工重新选择正确类别或重新切片；不要批量将 unknown 改为正确。

本项目训练的是视频动作分类器。它不需要每帧物体框，但如需位置框、每张物品计数、多人物动作定位，需要另外的数据和模型头，不能通过只给整个片段一个动作标签获得可靠定位。

## 训练机制

- 网络：R3D-18，Kinetics400 预训练，替换最终分类层。
- 标签：离散动作类别；不是逐帧监督。
- 时间：默认每片段随机取 2 秒，采 16 帧，训练进行时间位置随机化；评估取中央窗口。
- 图像：BGR 转 RGB；统一官方归一化、128×171 resize、112×112 中心裁剪。
- 少样本：可先 freeze_backbone=true，训练分类头，再用更低学习率解冻。
- 选择：验证集 macro-F1 最好的权重，测试集不参与选择。
- 类别不平衡：优先补充独立样本，报告每类召回；当前没有默认开启类权重或自动采样平衡。

片段最好接近时间窗口且动作单一。较长片段若含准备/操作/结束三种动作，仅给“操作”标签会污染随机窗口训练。

## 验收

片段分类评估看每类召回、混淆矩阵和“错误被判正确”比例；完整流程还要人工记录动作时间段，检查提醒时刻、误报、漏报、顺序、断线和会话边界。

unknown_rate 仅是置信度阈值下的拒识比例，模型遇到新动作仍可能高置信度误判。要采集实际其他动作/背景反例，不能把 softmax 当成经过校准的可靠概率。
